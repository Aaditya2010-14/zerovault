ZeroVault

An encrypted password manager, TOTP 2FA generator, secrets scanner, and local web dashboard — built entirely on the Go 1.27 standard library. No third-party runtime dependencies. No custom crypto.

View on GitHub Read the docs

01What it does

Encrypted vault

AES-256-GCM authenticated encryption, PBKDF2-HMAC-SHA256 key derivation at 100,000 iterations, fresh crypto/rand nonce on every save.

TOTP 2FA

RFC 6238-compliant codes compatible with Google Authenticator and other standard apps — HOTP built from crypto/hmac + crypto/sha1.

Secrets scanner

Walks a directory for leaked API keys, tokens, and high-entropy secrets — 18 named patterns plus Shannon-entropy generic detection.

Web dashboard

A local, loopback-only browser UI for everything above — CSRF-protected, session-cookie authenticated, auto-escaped templates.

File encryption

zerovault encrypt/decrypt — any file, streamed in 64KB chunks under chunked AES-GCM, independent of the vault's master password.

Built-in attack suite

zerovault attack runs 12 real attacks — brute force, tampering, XSS, CSRF, session hijacking — against a disposable fixture vault and reports pass/fail.

Single binary

go build -o zerovault ./cmd/zerovault — one command, no external files, templates and assets embedded via //go:embed.

02Zero-dependency stack

Every building block below is Go 1.27 standard library — nothing else appears in go.mod.

crypto/aes crypto/cipher crypto/hmac crypto/sha256 crypto/sha1 crypto/rand crypto/subtle encoding/base32 encoding/json/v2 uuid net/http html/template log/slog embed

03Quick start

go build -o zerovault ./cmd/zerovault

./zerovault init
./zerovault add github --username dev@example.com
./zerovault get github -copy

./zerovault totp add github-2fa --generate
./zerovault totp list

./zerovault scan .

./zerovault encrypt report.pdf
./zerovault decrypt report.pdf.enc

./zerovault serve          # http://127.0.0.1:8787

./zerovault attack         # run the built-in security audit

04Threat model summary

Protected against

  • Offline vault theft (PBKDF2 + AES-256-GCM)
  • Vault tampering (GCM authentication tag)
  • Nonce reuse (fresh crypto/rand nonce per save)
  • XSS in the dashboard (html/template auto-escaping)
  • CSRF (net/http CrossOriginProtection)
  • Session hijack via XSS (HttpOnly, SameSite=Strict cookies)
  • Clickjacking, MIME sniffing, referrer leakage
  • Unthrottled password guessing via the web UI

Explicitly out of scope

  • Keyloggers / memory forensics on the local machine
  • Master password reuse across services
  • GPU/ASIC-accelerated offline brute force (PBKDF2 is not memory-hard)
  • Network eavesdropping — loopback-only, plain HTTP, not TLS
  • TOTP code brute force (expected — see README)

Full threat model, design rationale, and every claim's supporting test: see README.md.
