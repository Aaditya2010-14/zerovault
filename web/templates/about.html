Generate 6-digit two-factor codes compatible with Google Authenticator. Implemented directly from RFC 6238 using HMAC-SHA1 — verified to match real authenticator apps.

Secrets Scanner

Scan codebases for leaked API keys, tokens, and passwords. Pattern matching for known formats plus Shannon entropy analysis for unknown secrets — and it respects .gitignore, so files that won't ever reach the repo are never flagged.

regexp math filepath entropy .gitignore-aware

Git History Scanner

Walks a repository's commit history by reading .git/objects directly — no shelling out to git — to catch secrets that were committed and later deleted, which a plain directory scan can never see.

File Encryption

Encrypts any file in 64KB chunks, each sealed under its own AES-GCM nonce with the chunk length and last-chunk flag bound into the tag, so truncation or tampering is rejected before any plaintext is written.

Why AES-GCM over AES-CBC?
GCM provides authenticated encryption — it detects tampering automatically.
Why PBKDF2 over Argon2?
Argon2 lives in golang.org/x/crypto, which is NOT part of Go's standard library.
Why SHA-1 for TOTP?
RFC 6238 specifies it. Google Authenticator expects it. HMAC-SHA1 remains secure.
Why crypto/rand, never math/rand?
math/rand is deterministic — knowing the seed lets you predict every output.

PROTECTED

  • ✓ Offline vault theft — PBKDF2-HMAC-SHA256 at 100,000 iterations makes each password guess measurably slow
  • ✓ Vault tampering — GCM's authentication tag detects any bit flip, truncation, or byte injection, rejecting it outright
  • ✓ Nonce reuse — every save draws a fresh 12-byte nonce from crypto/rand, never derived or counted
  • ✓ XSS in the dashboard — all user data renders through html/template, auto-escaped by output context
  • ✓ CSRF against the dashboard — every mutating route rejects cross-origin requests via net/http's CrossOriginProtection
  • ✓ Session hijacking — HttpOnly, SameSite=Strict cookies with a 15-minute sliding expiry
  • ✓ Clickjacking & header-based attacks — X-Frame-Options, CSP, and no-store caching on every response
  • ✓ Unthrottled login guessing — the web unlock form adds delays and a lockout on top of PBKDF2's own cost
  • ✓ Tampered encrypted files — each 64KB chunk is independently authenticated, so cuts or edits are rejected
  • ✓ Clipboard scraping — copied passwords are cleared from the clipboard automatically after 10 seconds
  • ✓ Weak passwords — crypto/rand generates unpredictable passwords
  • ✓ Timing attacks on 2FA — constant-time comparison via crypto/subtle

NOT PROTECTED

  • ✗ Keyloggers & screen capture — no application can defend against OS-level input capture
  • ✗ Memory forensics — plaintext exists in process memory while the vault is unlocked
  • ✗ Password reuse — a leaked master password compromises the vault wherever it's reused
  • ✗ GPU/ASIC attacks — PBKDF2 is less resistant than Argon2, which isn't in Go stdlib
  • ✗ Network eavesdropping — the dashboard is loopback-only, but the connection itself is plain HTTP, not TLS
  • ✗ TOTP code brute force — a 6-digit code space is exhaustible in under a second; real protection is the relying party's rate limit
