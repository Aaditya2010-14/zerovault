Why AES-GCM over AES-CBC?
GCM provides authenticated encryption — it detects tampering automatically.
Why PBKDF2 over Argon2?
Argon2 lives in golang.org/x/crypto, which is NOT part of Go's standard library.
Why SHA-1 for TOTP?
RFC 6238 specifies it. Google Authenticator expects it. HMAC-SHA1 remains secure.
Why crypto/rand, never math/rand?
math/rand is deterministic — knowing the seed lets you predict every output.

PROTECTED

  • ✓ Vault access — AES-256-GCM makes the file unreadable without the master password
  • ✓ Brute force — PBKDF2 with 100K iterations limits attempts to ~3-5/second
  • ✓ Tampering — GCM authentication tag detects any modification
  • ✓ Weak passwords — crypto/rand generates unpredictable passwords
  • ✓ Timing attacks — constant-time comparison via crypto/subtle

NOT PROTECTED

  • ✗ Keyloggers — no application can defend against OS-level input capture
  • ✗ Memory forensics — plaintext exists in process memory while unlocked
  • ✗ Password reuse — a leaked master password compromises the vault
  • ✗ GPU attacks — PBKDF2 is less resistant than argon2 (not in Go stdlib)
