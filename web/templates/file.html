Decrypt a file

The original filename is recovered from the encrypted file's own metadata. A wrong password or a tampered/truncated file is rejected outright.

How it works

Your file is buffered server-side in a temp directory that only this process can read, never written anywhere the browser could collide with it.
A key is derived from your password with PBKDF2 and a fresh random salt — the same derivation the vault itself uses.
The file is encrypted with AES-256-GCM in 64KB chunks, so large files never need to fit entirely in memory.
The result streams back to your browser as a download, and every temp file is deleted before the request finishes.
